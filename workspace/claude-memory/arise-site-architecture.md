Wix classic Editor + Velo. Wix has no REST API for layout, so whole pages ship as **Velo custom elements** in `public/custom-elements/`. Pattern: CMS collection → backend web module (`content.web.js` etc.) → page code (`$w.onReady`, sets a `data-*` attribute with `JSON.stringify`) → element reads the attribute and renders; Page Content text/images apply through `data-ck` / `data-ci` hooks. Forms POST to `/_functions/ariseForm` (`backend/http-functions.js` → FormSubmissions, then Contacts + an Automations trigger).

- **Local project:** `<repo>/workspace` (not a git repo). `files/` = files.zip (docs, mockups, images, CSVs, older element JS); `files2/` = ARISE-HANDOFF.md, AUDIT-REPORT.md, `arise-fixed-2026-08-23/` (the Aug 23 set, never installed).
- **Current deliverable:** `files2/arise-fixed-2026-09-14/` — see [[arise-fix-build-2026-09-14]].
- **Live code saved locally (2026-09-14):** `files2/live-elements/src/*.js` (exact 19 published element sources), `files2/live-backend/` (7 backend files Bradly pasted), `files2/live-page-code/` (pasted page code) and `files2/live-page-code/recovered/` (all published page code, named `<Page>.<pageId>.js`). Pasting these back undoes the fix build.
- **Recover live code without the Editor:** each published element loads from `https://bundler-velo.parastorage.com/v_metaSiteId_5fff0585-70f7-4075-9289-b6e4e3d38059/gridAppId_<grid>/filePath_public_delimiter_custom-elements_delimiter_arise-<tag>.js/...`; its source map `https://bundler.wix-code.com/<metaSiteId>/undefined/<grid>/custom-elements/arise-<tag>.js.map` has the original in `sourcesContent`. Page code maps: `.../pages/<pageId>.js.map` (entry `public/pages/<pageId>.js`); page ids appear in the browser console ("Running the code for the X page ... open <pageId>.js"). Grid id on 2026-09-14 was `c1613cca-9c4d-428b-bf13-67ae765354a9` (changes on every publish).
- **Elements → pages:** arise-header + arise-footer sitewide; arise-home `/`; arise-about `/about`; arise-leaders `/leaders`; arise-ministries `/ministries`; arise-sermons `/sermons`; arise-events `/events`; arise-contact `/contact`; arise-bible `/arise-bible` (bible-api.com direct, no page code); arise-serve `/serve`; arise-connect `/connect-groups`; arise-creatives `/creative-arts` + `/praise-worship /musicians /production /sound /media-team /content` via `data-dept`; arise-classes `/classes`; galleries arise-childrens `/childrens`, arise-youth `/youth`, arise-outreach `/outreach`, arise-leadnetwork `/lead-network` (Portfolio projects → `data-photos`); arise-alexandria `/arise-alexandria` (NOT `/alexandria`). Optional/not placed: arise-service-times(-final), arise-form.

- **App data:** Portfolio projects Children's `621e6fdb…`, Youth `c2be296e…`, Outreach `78e5e5f9…`, Lead Network `885f9ceb…`, Exciting News `b2697282…` (almost no items); Events ~20 (The Outpour 30 Oct 2026 upcoming); Online Programs 0 published; Members 82; installed site packages are all `@wix/*` npm packages (no Velo Packages).
- **Velo gotchas:** custom elements only work on the published site (Editor/Preview use an iframe; `/_functions/` don't run in Preview); `$w('#id')` returns one element with no `.length`; `$w('*')` is not a selector — use `$w('CustomElement')` (array); retry loops without a final warning fail silently; Velo `setAttribute` reflects into the DOM, so the browser console shows what landed; element code pasted into page code throws "document is not defined"; custom-element text is invisible to Google; deleting a Velo file only affects the site at the next publish.
- **YouTube gotchas (verified 2026-09-14):** YouTube serves the mobile site to a generic User-Agent — send a desktop Chrome UA; channel RSS feeds return 404; the channel `/live` page points at upcoming scheduled streams too (live only if playabilityStatus OK + isLive + not isUpcoming); the Shorts tab lists Shorts newest first as `shortsLockupViewModel` with `shorts-shelf-item-<id>` and `primaryText` title; vertical thumbnail `i.ytimg.com/vi/<id>/frame0.jpg`. (2026-10-27) `/streams` is the Live tab, newest first; `playlist?list=` pages list videos in the owner's order, so `youtube.jsw` picks the newest by YouTube's own "Streamed N days ago" text (`ageDays`); playlist cards are `lockupViewModel` with `contentId` PL…, `"N videos"` badge and an `i.ytimg.com/vi/<videoId>/` thumbnail. Playlists: Sunday Sermons `PLb-9QSfkRhnE2aI5nXA_Vv-UJDr8Fn4mI`, Apostle Bryant `PLa-Nxr2f-qHY`, Pastor Vanessa `PLeDfl1m-bAzo`, Glory Nights `PLYhdT3QigNmY` (13-character PL ids are real). The Live tab and playlist page fixtures in `workspace/sample-site/tests/fixtures/youtube-streams*.html` / `youtube-playlist-glory*.html` are synthetic (YouTube is unreachable from the cloud container), the shorts/playlists/live ones are real saved pages.
- **Deploying code:** the Wix REST API cannot deploy Velo code. Options: paste in the Editor, or Git Integration & Wix CLI for Sites (works on Wix Editor sites; blocked only by Velo Packages, which this site doesn't have).

## GitHub integration (connected 15 Sept 2026)
- Repo Rehchu/arisechurch; local clone `<repo>`. Layout: `src/backend`, `src/pages/<Page Name>.<pageId>.js` (masterPage.js), `src/public/custom-elements`, plus `wix.config.json` (siteId 5fff0585-…, uiVersion).
- While connected, the Editor code panel is read-only: change code by pushing to main. Publish from the Editor or `wix publish` (Latest commit); never publish Local code. `wix preview` (Local code) gives a real preview URL for testing without touching live or the repo.
