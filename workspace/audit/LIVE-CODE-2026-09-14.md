## 4. The three page-code defects

Each was checked against the Velo reference and adversarially reviewed (workflow of 14 Sept). The
Velo `$w()` reference documents exactly three selector forms — `#id`, a type name such as
`CustomElement`, and a comma list — and says an `#id` selection returns **one Element object**, while
a type selection returns **an array, even for zero or one match**.

**A. Eleven pages target an element ID that is not on the page — confirmed.** Identical code lands
on Home, Events, Ministries, Contact and Leaders with `#customElement1`, and Alexandria, the hub and
Classes had to be pointed at `#customElement5` to work; the eleven failing pages log the successful
fetch and then nothing reaches the element. The exact ID on those pages is still unverified
(right-click the element → View Properties). Fix: select by type — `$w('CustomElement')[0]` — so the
ID no longer matters, and add a final `console.warn` to every retry loop so a miss is never silent.

**B. Past Sermons dies on `if (!$w(EL).length)` — confirmed, but the cause behind it is not
settled.** A single-element selection has no `.length`, so the guard bails even when the ID is
right; if the ID is also wrong it bails for that reason instead. The typeof-setAttribute retry alone
would NOT fix a wrong ID (the eleven pages above prove that). Fix: the same type selector as A.

**C. masterPage.js never finds any element — confirmed.** `$w('*')` is not a documented selector,
and the loop exits silently after 30 tries; on /contact the page's own code puts `data-content` on
`<arise-contact>` while `<arise-header>` and `<arise-footer>` in the same DOM have no attributes at
all. Consequence: the 11 `site.*` keys (tagline, campus names, service times, email) never reach the
header or footer, and About, Ministries, Events, Leaders and Sermons get no CMS text.
Fix: `$w('CustomElement').forEach(el => el.setAttribute('data-content', json))` — documented,
returns an empty array on pages with no element instead of erroring.
